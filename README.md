# UE23CS352A: Machine Learning Hackathon - Hangman

This repository contains the complete solution for the **"Hackman Challenge 1"**, a Machine Learning Hackathon organized by the **Department of Computer Science and Engineering, PES University**.

The goal of this project is to create an **intelligent Hangman assistant** that uses **Machine Learning** to guess letters and solve puzzles with maximum efficiency.  
The entire implementation is contained in the **`ml_hackathon_hangman.ipynb`** notebook.

---

## Challenge Mandate

The challenge requires building a **hybrid system** that combines **probabilistic modeling (HMM)** and **reinforcement learning (RL)**.

### Part 1: Hidden Markov Model (HMM) — The Oracle
- The HMM is trained on the provided `corpus.txt` file (50,000-word dataset).
- It estimates the probability of each remaining letter appearing in the blank spots, given the current game state.

### Part 2: Reinforcement Learning (RL) Agent — The Brain
- Uses the probability distribution generated by the HMM to choose the optimal next letter to guess.

### Dataset
- The only data source allowed is `corpus.txt`.
- No external word lists or pretrained models are used.

### Evaluation
The agent plays **2000 games**, each allowing **6 wrong guesses**.  
The final score is computed as:

\[
\text{Final Score} = (\text{Success Rate} \times 2000) - (\text{Total Wrong Guesses} \times 5) - (\text{Total Repeated Guesses} \times 2)
\]

## Solution Overview

The solution is fully implemented in **`ml_hackathon_hangman.ipynb`**, following the hybrid design mandated by the challenge.

### 1️ Character HMM (Oracle)
Implemented as the `CharHMM` class.

**Training Process**
- **Initial Probabilities (π):** Probability of each letter being the first character of a word.
- **Transition Probabilities (A):** Bigram probabilities \( P(\text{current} | \text{previous}) \).

**Prediction Process**
- Filters the corpus for words that match the current masked word and exclude wrongly guessed letters.
- Computes a weighted frequency of all unguessed letters to form the final probability distribution over letters.

---

### 2️ Reinforcement Learning (RL) Agents

#### Environment: `HangmanEnv`
Simulates the Hangman game and defines the state, actions, and rewards.

| Event | Reward |
|--------|--------|
| Win | +10.0 |
| Correct Guess | +1.0 |
| Repeated Guess | -0.5 |
| Wrong Guess | -1.0 |
| Loss | -5.0 |

---

#### Agent 1: Tabular Q-Learning
- **Class:** `QLearningAgent`
- **State:** `masked_word` + "|" + `guessed_letters_bitmask`
- **Policy:** Epsilon-greedy exploration with decaying epsilon
- **Pros:** Easy to implement  
- **Cons:** Very large discrete state space; slow learning convergence

---

#### Agent 2: Deep Q-Network (DQN)
- **Class:** `DQNAgent`
- **Network:** Implemented using PyTorch (`DQNNet`)
- **State Vector (size 53):**
  - 26 values → HMM probability vector  
  - 26 values → Guessed letter mask  
  - 1 value → Normalized lives remaining
- **Training Techniques:**
  - Target network for stable learning  
  - Experience replay buffer (using `deque`)
